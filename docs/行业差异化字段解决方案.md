# 行业差异化字段解决方案

## 背景

当前系统存在前后端字段不对等的问题：
- **前端**：已实现按行业（化工/能源/农副/有色）显示不同列配置（`industryColumns`）
- **后端爬虫**：虽然有行业解析方法，但主流程只调用 `_parse_benchmark_price()`，大部分字段为空
- **数据库**：字段结构完整（specification, brand, unit, region, supplier 等），但数据填充率低

---

## 解决顺序：三阶段

### 阶段一：完善爬虫字段提取（后端优先级最高）

**目标**：让爬虫能正确提取各行业的差异化字段数据

**修改文件**：`backend/scrapers/shengyishe.py`

**具体任务**：

| # | 任务 | 化工 | 能源 | 农副 | 有色 |
|---|------|------|------|------|------|
| 1 | 激活行业解析方法 | `_parse_chemical_detail` | `_parse_energy_detail` | `_parse_agri_detail` | `_parse_nonferrous_detail` |
| 2 | 修复 `run()` 主流程调用 | 调用各行业解析方法替代仅 `_parse_benchmark_price` | 同左 | 同左 | 同左 |
| 3 | 设置行业差异化单位 | 元/吨 | 元/立方米 | 元/吨 | 元/克 |
| 4 | 完善字段解析 | name/spec/brand/price_type/region/supplier | spec/quantity/spot_type/region/valid_time | name/category/grade/brand/price_type/region | purity(as spec)/brand/price_type/region |

**完成标准**：
- [ ] 爬虫运行时日志显示各行业字段提取数量
- [ ] 数据库 `price_records` 表中 `unit` 字段按行业正确填充
- [ ] `extra_data` 字段包含行业特有的 key（如能源的"数量"、"有效时间"，有色的"品名/纯度"）

---

### 阶段二：后端 API 字段映射（前后端对接）

**目标**：确保后端返回的数据包含行业特有字段，前端能正确解析

**修改文件**：
- `backend/api/routes/prices.py` — `PriceRecordResponse` 和 `/prices/latest` 响应
- 前端根据需要可能调整

**具体任务**：

1. **统一 `extra_data` 到主字段**
   - 将 `extra_data` 中的常用字段（如"规格"、"品牌/产地"）提取到主表字段
   - 能源的"数量"→考虑新增 `quantity` 字段 或保留在 `extra_data`
   - 有色的"品名/纯度"→已映射到 `specification`

2. **修改 `/prices/latest` 响应**
   - 当前只返回基础字段（price, trend, change_percent, source 等）
   - 需增加返回 `specification`, `brand`, `price_type`, `region`, `supplier`, `unit`

3. **验证字段完整性**
   - 检查 `PriceRecordResponse.from_record()` 是否所有字段都已映射

**完成标准**：
- [ ] `/prices/latest` 返回完整字段列表（specification, brand, unit, region, supplier, price_type）
- [ ] `unit` 字段按行业正确返回（元/吨、元/立方米、元/克）
- [ ] 前端表格能显示所有字段，无 undefined/null

---

### 阶段三：前端行业差异化展示优化

**目标**：让前端列配置与后端数据完全匹配，实现"行业化"展示

**修改文件**：`frontend/src/views/Dashboard.vue`

**具体任务**：

1. **细化 `industryColumns` label**
   ```javascript
   // 示例：让不同行业的同一 prop 有不同 label
   industryColumns = {
     '化工': [{ prop: 'brand', label: '品牌/产地' }],
     '能源': [{ prop: 'brand', label: '产地' }],  // 能源无 brand，显示"产地"
     '农副': [{ prop: 'brand', label: '产地' }],
     '有色': [{ prop: 'brand', label: '产地' }]
   }
   ```

2. **按行业隐藏空字段列**
   - 如果后端返回的 `brand` 为空，前端自动隐藏该列
   - 或在 `industryColumns` 中精确配置每个行业显示哪些列

3. **行业化单位展示**
   - 在表格中显示行业对应的单位（来自 `unit` 字段）
   - 不再写死"元/吨"，而是动态显示

**完成标准**：
- [ ] 选择"有色"时，表格显示"产地"而非"品牌/产地"
- [ ] 选择"能源"时，不显示"报价类型"、"交易商"列（或显示但数据为空）
- [ ] 单位列正确显示：化工→元/吨，能源→元/立方米，有色→元/克
- [ ] 与阶段二联动验证：后端有数据的字段前端都能显示

---

## 数据流全貌

```
生意社网站
    ↓ (爬虫抓取)
backend/scrapers/shengyishe.py
    ↓ (行业解析方法提取字段)
price_records 表 (unit, specification, brand, region, supplier, extra_data)
    ↓
backend/api/routes/prices.py (/prices/latest)
    ↓ (返回完整字段)
frontend/src/views/Dashboard.vue
    ↓ (industryColumns 映射)
表格显示 (行业化列配置)
```

---

## 各阶段依赖关系

```
阶段一（爬虫）→ 阶段二（API）→ 阶段三（前端展示）
    ↑              ↑              ↑
 必须先完成    才能验证数据    最终呈现效果
```

---

## 验证方式

1. **阶段一**：手动运行爬虫，检查数据库 `price_records.unit` 是否正确
2. **阶段二**：调用 `GET /api/v1/prices/latest?industry=有色`，检查返回的 unit 是否为"元/克"
3. **阶段三**：前端切换行业，表格列 label 和单位是否正确变化
